## How to use this file

- Work one area per round. For each row, answer in the Call column or next to it:
  - ✅ accept my call as written;
  - ✂️ cut it (whatever my call was);
  - ✏️ change it, with a note.
- Then answer that area's "Questions for David". Each question has my recommendation; "yes" means take it.
- Ids: `D<n>` is row n of the design inventory (`design-inventory.md`, design line numbers in the Evidence column as `L<n>`). `N<area>.<n>` is a new row from the vault reports. Vault evidence is cited as `[[card#eN]]`.
- Status comes from the 2026-10-22 implementation status report plus spot checks of the code: **built** (code and unit tests; nothing is lab-proven), **partial**, **missing**, **n/a** (prose, procedure or principle), **?** (not sure).
- Calls: **KEEP** (as designed), **CHANGE** (Why says how), **CUT** (delete from the design; if built, delete the code, git history is the archive), **ADD** (new). Cuts of built code are marked **[deletes code]**.
- Module: where it lives under the module contract. `core` means the small core (link, spool, exec, event store, manifest, UI shell). A module name in *italics* is a proposed new opt-in module (off unless the manifest enables it). "content" means rules, plans or checks YAML rather than Go.

## Decisions so far (apply; don't re-ask)

1. **Module contract.** Every capability is a module: one package, one config block, declared events consumed and emitted, a capability manifest (OS, privileges, roles, resource budget), health, its own tests, passes a shared conformance suite, no sibling imports (modules talk only through typed events). Controller analyzers are pure functions over event-store queries. Content before code: prefer rules, plans and checks YAML over new Go. New capabilities are off unless the manifest enables them. Small core: link, spool, exec, event store, manifest, UI shell.
2. Cut code is deleted; git history is the archive.
3. **Ignore all CCDC competition rules** (packet rules, repo rules, workstation and tooling limits, Nationals rules, "ask officials" items). Drop findings that exist only because of a rule. Scoring mechanics stay valid evidence: how Quotient checks services, how points accrue, organizer scans scoring extraneous services, Orange Team as a scored component.
4. No event profiles (invitational, regional, ...). Controller placement is just config.
5. Never mass-rotate credentials. Learn which accounts the scorer actually uses.
6. Injects: no prewritten inject responses in Phylax. Only generators for recurring artifacts (network diagrams, inventories, port tables, firewall exports, evidence captures and similar).
7. The design follows the code where the code chose differently: audit netlink plus sock_diag instead of the proc connector; pure-Go PDF (fpdf) instead of Typst.
8. D-1 to D-9 stand (binary integrity alert-only; lightweight chains; Kali as external monitor; controller on the LAN; cache everything locally; hiding is fine; OSS alongside is fine; Quotient is the scorer). D-6 "full rewrite, no triage" is replaced by: scope is whatever survives this review, and accepted items aren't cut for time.
9. No time goals.
10. **New evidence, MWCCDC Discord 2026-10-22** (`ccdc-private/knowledge-base/inbox/david/2026-10-22-mw-discord-quotient-scoring-users.md`, organizer Jimmy and red teamers), applied in area 7:
    - Quotient shows the users it scores with; no admin accounts are used for scoring. So "learn the scorer's accounts" means read the credential lists from Quotient, with auth-log confirmation as a backup, not a big discovery engine.
    - PCRs are submitted inside Quotient and take effect immediately. There are a lot of scoring users; mass rotation is a bad play. Red does not have the scoring user list.
    - Quotient has several credential lists, possibly per service; one password change may need PCRs on several lists. Track credentials per credlist.
    - Quotient doesn't know about reverts: after a host or AD revert the passwords roll back but Quotient keeps the new ones. A revert needs a re-sync.
    - Team-pack passwords are admin-only and leak fast (full domain dump about 10 s after drop flag at Nationals, cleartext about 20 s). Admin and service credential rotation is a T+0 action, ahead of enrollment or anything else.
11. **No AI or MCP assistant module and no operator-AI rulebook** (David: MWCCDC does not use AI). Peer proposals for one (UCI bonfire `hypernova`) are rejected.
12. **The MWCCDC Defender Toolkit will not be run by us.** No coexistence work (nft flush collision, audit and Sysmon baselines) is planned.
13. **Never restrict source addresses on scored service ports.** Quotient uses a lot of source IPs; any rule touching scored inbound must be allow-any-source on the scored ports. It is an explicit scoring-safety lint rule (D172). Management-port blocks (Windows stage-0) apply to management ports only.
14. **Peer-platform review (UCF RedBaron2 family, UCI bonfire, COAL/Salt/Ansible/winners, Falco/Wazuh/Splunk stacks, osquery/Velociraptor/Elastic):** accepted as yes: coverage board (N11.6), UCF rootkit cross-checks as hunt content (D80), hash of our own audit rules in the heartbeat (D91). Pending David: noexec remount (A5.Q3), per-executable egress (A6.Q3), eBPF/Rust (A2.Q2).

## Cross-cutting design ideas

1. **Rewrite the design around modules.** One section per module: purpose, config block, events in and out, capability manifest, health, tests, evidence that it scores. The current design is organised by topic, so the same capability shows up in five sections (for example PCR in Execution, Active checks, Credentials, Kali and Ops).
2. **Evidence column per module.** Every module states the vault evidence for points impact. A module without evidence starts off and is a cut candidate at the next review.
3. **One rule-id namespace with a registry check in CI** (prevents bug 2).
4. **Credentials keyed by (account, credlist)** everywhere: accounts.yml, PCR engine, verification, CSV, revert re-sync.
5. **T+0 is a console phase, not an agent phase.** Admin rotation, Zerologon, Palo management lockdown and reading Quotient credlists happen before enrollment; the platform's first job is to record what was done at T+0 (operator ticks in the live checklist) and to evict sessions once agents arrive.
6. **Generators share one engine.** Inventory, port tables, diagrams, firewall exports, evidence runs, traffic reports and IRs are queries plus a renderer (PDF or file). One `report` module with content-defined generators, instead of one Go file per artifact.
7. **Analyzers as pure functions with fixture tests** (traceback, chains, deps, SLA, egress ranking, vuln matcher): fast tests, and each can be switched off without touching the others.
8. **Procedures leave the design.** Team runbooks (timelines, roles, callouts, SOC rotation) move to a runbook doc; the design keeps only what code must support.
9. **Rule-format extensions.** Falco-style `lists:`, `macros:` and per-rule `exceptions:` so allowlists come from the manifest without forking rule text; a `maturity:` tag that sets the default mode; a per-rule `rate:` cap that emits a "suppressed N" summary; `requires: {os, role, module}` preconditions, the same field in rule, check, hunt and plan YAML so one pack hits Linux and Windows and a non-matching item is skipped and reported; a `schema` version per event type checked by the conformance suite.
10. **Suppression records.** Anything silenced (a tag exemption, a known-benign override) carries reason, owner, added date and optional expiry, created from an alert in the UI. Replaces silent exemptions and separate low-level override rules.
11. **Typed ad-hoc queries, no query language.** `probe.run{name, params}` over `inventory` tables and hunt checks, with differential snapshots (added, removed, changed, epoch) as the table contract. No SQL or VQL on the host.
12. **Label targeting.** Hosts carry labels; plans, hunts and approvals target a label expression.
13. **Per-module budget in the heartbeat.** CPU ms, RSS and bytes out per module, so a runaway rule is visible and the conformance suite can check "respects budget".
14. **`validate` hook on config writes.** A typed validator (`sshd -t`, `visudo -cf`, `nginx -t`, `nft -c`, ...) runs on the temp file before the atomic rename.
15. **Grouped multi-host results.** Collapse identical outputs ("14 same, 2 differ"), outliers first, with per-host status; the convergence board (N11.7) uses the same grouping.
