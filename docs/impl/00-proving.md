# W0 Proving Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove that today's v3 code builds, vets and passes its tests (with `-race`) on both OSes, fix whatever does not, and list every `t.Skip` so the lab gate knows what is not exercised.

**Architecture:** No new code. A baseline run is recorded in `docs/impl/w0-results.md`; each real failure becomes one root-cause fix in shared code with its own commit; the skip list is generated by one command into `docs/impl/w0-skips.md`. Lab work (running skipped tests as root, on Windows) is the last task and is not done by Haiku.

**Tech Stack:** Go 1.27.2 (mise), GNU make, gcc (needed by `-race`), GitHub Actions `ci.yml`.

**Spec:** `phylax_design.md` (v4) "Testing and lab" and the repo rules in `AGENTS.md` ("A package is done when CI is green (build for both OSes, vet, test, `-race`)"). The user's brief for this plan: "just needs to pass tests".

## Global Constraints

- Go 1.27.2 via mise; `CGO_ENABLED=0` for builds. `make build build-windows vet test race` must pass at every commit (the one exception is documented in Task 2: the race job needs `CGO_ENABLED=1` and gcc).
- Small commits, one logical change each, message `area: summary` (for example `make: race job builds with cgo`). **No attribution lines** (no `Co-Authored-By`, no session links, no "Generated with") in commits.
- Tests exercise the real code; do not mock the code under test, do not weaken or delete an assertion to make a test pass, do not add `t.Skip` to hide a failure.
- Fix the root cause once, in shared code, grep all callers of what you touch; one commit per fix.
- `shortcut: <limit>, <when to upgrade>` comment for any known limit you leave.
- Do not push; do not change `phylax_design.md`.
- Tests that need root, containers, nftables or Windows are skipped with a clear message when unavailable. Never turn such a skip into a silent pass.

## Review Focus

- A `-race` failure that only appears under load (run with `-count=3 -cpu 1,4`): flaky timing tests in `internal/controller`, `internal/e2e`, `internal/capture`. Expected: stable green over repeated runs, fixed with deterministic waits, not longer sleeps.
- `make race` run in an environment where `CGO_ENABLED=0` is exported (AGENTS.md tells agents to export it): expected to run the race detector, not stop with `go: -race requires cgo`.
- Windows-only code behind `//go:build windows`: expected compile-clean including `_test.go` files (`GOOS=windows go vet ./...` type-checks them; Task 1 and 3 run it).
- A skip that has become permanent because its guard condition is always true on the CI image (for example `os.Geteuid() != 0`): expected to be listed in `w0-skips.md` with its reason, so the lab gate runs it.
- A test that passes only because the machine has a tool installed (tcpdump, nft, docker): expected to skip with a message when the tool is absent, verified once with `PATH` stripped.

- [ ] **Step 1: Run the repeat sweep and record the output**


The last command runs with `PATH` holding only Go's own bin dir, so tcpdump, nft, docker and systemctl cannot be found. Tests must skip with a message, never fail.

Expected: no non-`ok` lines. Append the three commands and their outputs (first error line only) to `docs/impl/w0-results.md`.

- [ ] **Step 2: If anything failed, write the failing test first**

For each failure, reduce it to the smallest test that fails the same way (the failing test itself is acceptable if it already fails alone: `go test -race -count=20 -run '^TestName$' ./pkg`). Quote the test name and the failing assertion in the results file.

- [ ] **Step 3: Fix the root cause in shared code**

Rule: fix where the defect lives, not in the test. Allowed: replace a fixed `time.Sleep` with a wait on the event it stands for; add the missing lock or channel close; make a map iteration ordered; add a guard for a missing tool. Not allowed: raise a timeout without finding why, add `t.Skip`, loosen an assertion, or add a retry loop around the test. Before editing a function, `grep -rn 'FuncName(' --include='*.go' .` and check every caller. One fix per commit.

- [ ] **Step 4: Verify the fix 20 times**

Run: `CGO_ENABLED=1 go test -race -count=20 -run '^TestName$' ./pkg`
Expected: `ok`.

- [ ] **Step 5: Run the full gate and commit**

Run: `CGO_ENABLED=0 make build build-windows vet test race; echo exit=$?` (expected `exit=0`), then per fix:

```bash
git add <files>
git commit -m "<package>: <what was fixed>"
```

If Step 1 found nothing, there is nothing to fix: commit only the appended results (`docs: W0 sweep results`). Repeat Steps 2 to 5 for each further failure.
